Changes

Scheduled threads now replace Codex's inherited coding instructions with a
480-character game decision base instruction. Role instructions, strategic
guidance, model selection, reasoning effort, authentication and concurrent role
scheduling retain their existing behavior. Every initial/resumed generation
still supplies its complete strict role schema and uses the same thread for
receipts and decisions.

A local provider gate verifies the exact strict schema and forwards generation
requests with tools=[] and tool_choice=none. It admits at most one generation
attempt and one separately counted compaction attempt per host decision.
Internal disabled-tool continuations and transport retries are blocked before
another upstream request. Blocked continuation fails the activation, without
dispatching an incomplete decision or automatically starting another repair.
This deliberately bounds spending; its effect on gameplay completion still
needs live validation. Codex retains authentication; synthetic ChatGPT-token
and OpenRouter-key captures verify header preservation. The gate uses HTTP
streaming; the built-in OpenAI provider's WebSocket probe falls back locally
after HTTP 405. Provider headers and bodies are not written by the gate.

Reservations persist before forwarding, include failed/uncertain attempts, and
are never refunded. The default ceiling is 128 per activation workspace.
CIV_MODEL_REQUEST_BUDGET (an absolute SQLite path) and CIV_MODEL_REQUEST_LIMIT
share a finite ceiling across concurrent roles, processes, restarts and trials.
Reopening a budget with a different ceiling fails. The saved-position harness
exposes --max-model-requests for a shared suite budget and rejects unsupported
variants. These are Codex inference/compaction ceilings; the separate Decisions
backends retain their own closed-choice enforcement and cost budgets.

Routine structured inspections now let the host choose full/unchanged/delta
delivery. The optional recoverBaseline field requests full transport recovery
only for a missing or mismatched baseline. Content selection (including full
overview views) remains explicit. Detail projection/evidence checks still run;
no compact response grants stale or unseen inspection credit.

Independent memory writes, military operation notes and Economy requests can
continue within one action batch. Repeated edits to the same record/operation,
unseen intent citations, changed war goals, ownership transfers, invalidated
previews, failed actions and uncertain execution retain their fences.
Confirmed action receipts remain replayable without re-execution. Promises
remain exact authored, nonbinding text.

The decision journal correlates provider reservation IDs with decisions and
schema fingerprints. Failure reports separate request-budget failures from
argument, transport and gameplay failures. Attempt counts, provider usage,
Codex transport metrics and character sizes are separate; rejected local
requests and WebSocket probes are not counted as forwarded inference.

Offline results

Thirty local real-Codex capture cases cover Main, Economy, Military,
Communication, strategic review and both peace consultation phases, initial
and resumed turns, on OpenAI and OpenRouter transports. Every forwarded
generation has the intended strict schema, no advertised tools, tool choice
disabled and a stable thread cache key. MCP execution is absent. A forced
disabled exec response reaches the provider once; its continuation is blocked.
The pre-fix capture forwarded that automatic continuation.

The inherited runner prompt shrinks from 16,979 to 480 characters in these
synthetic captures. The unchanged 31-character test instruction brings total
instruction characters to 17,010 before and 511 after. Tool advertisement
shrinks from 1,357 to 2 serialized characters. Gameplay role guidance is not
represented by that test stub and was not cut. Full role schemas remain
complete and shrink slightly (roughly 246–249 characters); consultation
schemas are unchanged. These are character measurements, not billed tokens.

Verification

Focused batch, contract, delivery, recovery and harness checks passed. Atomic
admission tests exposed a concurrency race while parsing simultaneous request
bodies; the reservation check now occurs immediately before claiming the
window, with no intervening await. The regression fails before the fix and
passes after it. Shared SQLite ceilings, restart, interruption, redirects,
compaction and malformed formats are tested against local providers.

The initial full-suite attempt used a temporary directory under build/. That
made Unix socket paths too long and changed checkout discovery. Its failed
log is retained as full-suite.log. The clean run uses a short /tmp directory
and the virtualenv on PATH. Fake app-server fixtures now understand account
metadata and the explicit baseline recovery operation; scheduler assertions
check preserved model/effort plus the new request gate.

The corrected full Python suite passed: 2,611 tests and 76 subtests, with eight
skips (five container requirements and three opt-in installed-model checks).
The final focused run passed 80 tests after the admission race fix, including
all 30 real-Codex/local-provider capture cases. Ruff lint and formatting passed
(467 files); Pyrefly reported zero errors and 40 warnings; git diff --check
passed. Full and focused logs are retained as full-suite-verified.log and
final-focused.log. The engine checkout remains clean at the pinned revision.

Limits and rollout

The local synthetic tests cover Codex 0.164.0 and both provider transports. The
live comparison below additionally exercises the real ChatGPT backend. Live
OpenRouter behavior, dedicated Communication and review/consultation quality
remain untested. The gate's conservative treatment of uncertainty and HTTP
fallback may affect recovery or timing. An activation that tries a disabled
tool fails instead of buying an automatic self-correction.

The four current games retain their pinned images. Acceptance must compare
gameplay progress, semantic failures and total provider usage, not schema
validity or runtime alone. This candidate has not established equal-quality
efficiency and was not deployed to those games.

Protocol references: https://learn.chatgpt.com/docs/app-server and
https://learn.chatgpt.com/docs/config-file/config-reference. The installed
protocol and local captures take precedence over assumptions about optional
configuration. outputSchema constrains the final response; the request gate
provides the independent cost and tool-choice enforcement.
