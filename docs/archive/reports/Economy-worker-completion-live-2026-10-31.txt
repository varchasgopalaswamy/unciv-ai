Economy worker completion: live behavior check, October 31, 2026

Result

Both models completed one Economy pass with every remaining idle worker either
acted on or explicitly skipped. There were 9 provider attempts in total, below
the hard limit of 16. All 9 responses reported usage. No schema, gateway or
native execution errors occurred, and no disabled execution tool was attempted.
The completion requirement worked. Luna's economic choices remain questionable;
this does not establish improved gameplay quality.

Setup and isolation

Prepared Inca position pangaea-g4-inca, turn 156, identical to the previous saved
position comparison. Each model received fresh independent private memory and
an independent native engine copy. Models: gpt-6-luna and gpt-6.1-terra, medium
reasoning, strategy and civilization guidance enabled, no native advice or
Decisions backend. Production RoleRuntime, strict decisions, gateway validation,
completion checks and native actions were used.

Only Economy ran inference. The evaluator stopped the role after its confirmed
completion instead of waiting for a sibling or advancing the game. No Main or
Military model ran; no END_TURN was issued. This tests a single role's behavior,
not concurrent scheduling, diplomacy, subsequent worker turns or game outcomes.

Before inference, a separate local engine preflight verified the three idle
workers and rejected an empty finish without completing the role. It consumed
zero provider attempts. An initial evaluator import-path failure also occurred
before starting an engine or contacting a provider; the failure was corrected.

Limits: 8 actual provider attempts per model, including retries and compaction;
300 seconds per role; a 400,000 reported-token soft stop checked before the next
host decision. Neither live run hit a limit or required a relaunch.

Luna

Two responses: one batch of four native commands, then finish with an explicit
skip. unit6 began a Road; unit8 and unit10 began Remove Forest; unit7 was woken
from Sleep, then explicitly skipped with a reason that it had no current-tile
work options and would await further inspection. The sleeping worker had been
exempt initially; waking it correctly made it require a disposition.

The Road rationale was to connect Cuzco, but all cities were already connected.
The delivered Economy observation included development.unconnectedCities=[];
the full native observation independently confirmed every city connection.
Movement benefits could still justify a road, but that was not the stated reason.

Both forest removals replace existing Lumber mills. Native options showed a
30-production grant to each nearby city, with a recurring food loss for unit8's
tile and production loss for unit10's tile. Those tradeoffs can be legitimate,
but Luna did not explain why the short-term grants outweighed the ongoing loss
or record a subsequent improvement plan. Jobs were started, not completed.

The wake-and-skip decision also achieved no immediate useful work. unit7 stood
on Cuzco's city tile, explaining its empty work menu; movement was possible.
The three worker-job intents additionally used a nonexistent cityPlan value
"no-plan". This did not block these worker commands; it is an unsupported
metadata reference, not an actual city-plan record.

Terra

Seven responses: inspect cities/maps/plans; create four city plans and start
unit6 on a Farm; inspect two movement previews; move unit10; refresh unit8's
preview after that movement; move unit8; finish. unit10 reached an unimproved
forest tile with no movement remaining. unit8 retained travel toward unimproved
grassland after using its movement. The sleeping worker remained asleep, and
the existing worker job continued. No idle workers remained, so workerSkips=[]
was accepted. These choices preserved the existing Lumber mills. Their eventual
economic return was not measured because the game did not advance.

Historical comparison and limits

Previous Luna Economy: 1 response, 31,242 uncached input tokens and 25 output
tokens; no worker actions or explicit skips. Current Luna uses one more call,
6.51% more uncached input and 107.94% more total reported tokens. Its new work and
cache reuse explain why total-token growth alone is not a quality comparison.

Previous Terra Economy: 13 reported responses plus one interrupted response
with unknown usage; 98,597 uncached input tokens and 583,052 total reported
tokens. Current Terra uses 7 responses, 48.97% less uncached input and 45.64%
less total reported usage. The former run included sibling actions and a role
restart; these percentages do not isolate the causal effect of the new rule.

One sample per model, role isolation, different stochastic choices and cache
conditions limit comparisons. The test demonstrates completion behavior and
retains concrete semantic failures for follow-up. It does not justify a broader
quality or efficiency claim or a new full-game benchmark run by itself.
